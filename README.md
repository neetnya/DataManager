# 轻量数据管理工具

---

## 一、快速开始

```powershell
# 1) 检查运行环境（本软件不需要安装任何依赖，此脚本只做检查）
powershell -ExecutionPolicy Bypass -File .\install-deps.ps1

# 2) 构建，产物输出到 .\dist
powershell -ExecutionPolicy Bypass -File .\build.ps1

# 3) 运行
.\dist\DataManager.exe
```

> 如果双击 `.ps1` 提示“禁止运行脚本”，就在 PowerShell 里加上
> `-ExecutionPolicy Bypass`，或者先执行一次
> `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`。
> 所有 `.ps1` 都存成 **UTF-8 with BOM**，保证中文在 Windows PowerShell 5.1 下不乱码。

运行环境要求：**Windows 10 或更高版本** + **.NET 9 桌面运行时**。

## 二、关于依赖（重要）

**本软件不引用任何 NuGet 包**，因此不需要联网、也不需要执行任何安装命令。做法：

| 需要的能力 | 实现方式 |
|---|---|
| SQLite 存储 | P/Invoke 调用 **Windows 10 自带的 `winsqlite3.dll`**（系统内置 SQLite 3.43.2），完全不用 `Microsoft.Data.Sqlite` / `SQLitePCLRaw` |
| WebDAV 上传下载 | BCL 的 `System.Net.Http` + 手写 `PROPFIND` XML 解析（`System.Xml.Linq`） |
| 界面 | WPF（`Microsoft.WindowsDesktop.App` 共享框架，随 .NET 运行时提供） |
| CSV 读写 | 自行实现（RFC 4180），非 UTF-8 编码用 Win32 `MultiByteToWideChar` 解码 |
| 配置读写 | `System.Text.Json`（BCL 内置） |

├─ Data/                    轻量 SQLite 封装（连接、语句、事务、在线备份）
├─ Models/                  表 / 列 / 行 / 标签
├─ Services/                业务：表结构、行查询、CSV、WebDAV、备份、配置
├─ ViewModels/              界面绑定对象
├─ Themes/Theme.xaml        总体样式
├─ Dialogs/                 设置 / 备份恢复 / 添加数据 / 添加标签 / 输入框 / 自绘消息框

├─ install-deps.ps1         运行环境检查脚本
├─ README.md                本文件

> ⚠️ **`build.ps1` 的注意事项**
> - `build.ps1` 只清理 `dist` 里的**程序文件**，`Data\`、`Backup\`、`config.json` 会原样保留，发布后还会做一次校验。
> - 含中文的 `.ps1` **必须存成 UTF-8 with BOM**：PowerShell 5.1 会把无 BOM 的 `.ps1` 当 ANSI 读，中文乱码还可能把两行粘成一行，导致逻辑静默失效（曾经因此把 `dist` 里的用户数据整个删掉）。

## 五、数据库设计（第 14 条待确认项的落地）

### 5.1 元数据表

| 表 | 用途 |
|---|---|
| `meta_table` | 表清单（`id` / `name` / `sort_order`）。表名允许重复 |
| `meta_column` | 列配置（`ordinal` / `col_name` / 5 个标记位 / `sort_desc` / `sort_prio`） |
| `meta_tag` | 标签，`(table_id, name)` 唯一 |
| `meta_tag_link` | 标签绑定：`scope=0` 归属行，`scope=1` 归属分组值 |

### 5.2 动态 DDL 的映射规则

- 第 N 张用户表 → 真实表 **`t_<id>`**（用 `meta_table.id`，与表名无关，所以表名可以随便重名）
- 第 K 列 → 真实列 **`c<K>`**，列名存在 `meta_column.col_name`
- **物理列名一旦分配就永不复用、永不重编号**：删掉 `c1` 后新加的列是 `c3`，不会是 `c1`。
  这样删列/调序都不需要搬动任何数据，也不会出现列错位。
- 每一行有 `rid INTEGER PRIMARY KEY AUTOINCREMENT` 作为稳定行标识，标签靠它定位。
- 所有列都是 `TEXT`（需求：全是字符串），空字符串统一存成 SQL `NULL`（便于“空值不参与唯一”）。

### 5.3 排序优先级

`meta_column.sort_prio` 保存用户自定义的固定排序优先级，数字小的先排，同值回落到建表顺序。
`ORDER BY` 只在查询时拼进 SQL，**除设置里的排序外不提供任何其他排序操作**（点列头不会排序）。
没有勾选任何排序列时按 `rid` 排序，保证结果稳定。

### 5.4 本地备份保留策略

`config.json` 的 `BackupKeepCount`，**默认 0 = 保留全部**；可在“备份 / 恢复”窗口里改成保留最近 N 份并立即清理。

## 六、功能与需求的对应关系

### 主界面
- **打开即最大化**（关闭时记住的是普通状态下的窗口尺寸，取消最大化后回到这个大小）
- 顶部工具栏：左侧只有**齿轮图标按钮**（打开设置）；右侧是操作按钮，顺序为 添加 / 添加标签 / 删除行 / **快捷查询** / 清除筛选（【快捷查询】紧挨在【删除行】右边，仅在该表配了快捷查询列时显示）
- 左侧表目录（类似网页目录，窄栏，无标题文字），右侧对应当前表的表格
- **表格不分页**，靠 `DataGrid` 行虚拟化支撑大表滚动
- 每列列头一个独立搜索框：**模糊、大小写不敏感**；LIKE 的 `%` `_` `\` 已转义
- 列头不显示任何配置文字（唯一／排序等一律不显示），只有搜索框本身
- 分组列的列头是**可编辑下拉**，候选值为该列已有值（去重）。
  **没有“(全部)”选项**：清空输入框就等于全部，所以不再重复给一项；清空会立刻取消该列筛选
- 单元格：**单击选中、双击编辑、Ctrl+C / Ctrl+V 复制粘贴**；回车或失焦保存，**Esc 取消**
- 选中单元格只改变背景与边框，**文字颜色保持原样**
- 行号列（行头）颜色固定，滚动或选中时不会深浅交替
- 行选择支持 Ctrl / Shift 多选；`Delete` 或【删除行】**立即删除、无二次确认**，可用 **Ctrl+Z** 撤销（刻意设计；最多 10 步，无重做）
- 底部只显示行数统计（如「共 3 行」或「共 2 行（已筛选）」）
- **列宽会记住**：手动拖动列分隔线后写入 `config.json`，重开软件/切表/改列配置后都按记录恢复；
  没调整过的列仍自适应等分

### 标签
- 标签统一在表格上方的**标签条**里，是本软件唯一的标签入口（没有单独的标签搜索输入框）
- 每个标签一个按钮，后面括号里是**当前视图内带该标签的行数**
  - 行标签：算实际绑定的行
  - **分组标签：把该分组值下所有行都算进去**（同一行同时命中行标签与分组标签时只算一次）
- **左键**标签 = 按该标签**精确**筛选（再点一次取消筛选；不会把「测试2」算进「测试」）
- **右键**标签 = 重命名 / 移除标签（清除本表所有使用，标签本身保留）/ 删除标签（**二次确认**，文案带影响行数）

**移除标签有三个入口，职责区分清楚：**

| 入口 | 作用 |
|---|---|
| 单元格**右键菜单 → 移除标签** | 只解除当前这个单元格（所在行或所在分组值）的标签绑定，标签本身保留。菜单里会列出该单元格当前挂着的每个标签，点哪个移除哪个 |
| 【添加标签】窗口里每行的**【移除】/【添加】** | 同上，只影响当前单元格对应的归属对象 |
| 【添加标签】窗口里每行的**【删除标签】** | 从整张表彻底删除该标签（会提示影响多少行），**表格里的数据不动** |

- 点【添加标签】时按所选单元格决定归属：分组列 → 归属该分组值；其他列 → 归属整行
- 标签没有任何引用后会自动消失（行被删、分组值被改掉都会触发）

### 快捷查询
1. 点【快捷查询】→ 读剪贴板（**不做 trim / 去换行**）
2. **精确命中**（大小写不敏感）→ 被查询列的值写回剪贴板（直接覆盖），同时**表格跳转并选中该行**，无弹窗
3. **未精确命中但模糊命中** → 对当前表做筛选，出现【清除筛选】按钮
4. **完全无结果** → 弹窗提示
5. 无论当前是否已筛选，**始终在全表范围内查找**

### 唯一约束
- 语义是“**有值则列内唯一，空值不参与**”（不是 SQL 的 UNIQUE）
- 违反时**阻止保存 + 提示**；编辑已有行改成重复值同样处理，并把单元格还原
- 在编辑、添加、粘贴三条路径上都做了校验；校验与写入放在同一事务内

### 设置（独立窗口）
分「列配置」「数据」「外观」三个页签，改动**手动保存**。
- **列配置**
  - 建表 / 重命名表 / 删表（**二次确认，文案里带“该表有 N 行数据”**）
  - 加列 / 删列（删列时该列数据一并删除，会提示该列有多少非空单元格）
  - 快捷查询列与被查询列**每表各最多 1 个**，勾选一个会自动取消同类；保存时校验**必须成对存在**
  - 排序优先级可手工填数字，也可用【上移/下移】调整
  - 未保存关闭时提示“保存 / 不保存 / 取消”；选「不保存」则**回滚整个事务**，外观与分组分隔符也回到打开设置时的状态
- **数据**
  - 【导入 CSV】/【导出全部 CSV】/【本地备份与恢复】都在这里（主界面工具栏不再放这些按钮）
- **外观**（全局设置，立即生效）
  - 右侧表格的**字体、字号、行高、加粗、倾斜、是否显示网格线**
  - 带实时预览区；可一键【恢复默认外观】
  - 随【保存】一起写入 `config.json`

### 列宽记忆
- 手动拖动列宽后自动记住（写入 `config.json` 的 `ColumnWidths`）
- 重新打开软件、切换表、或改动列配置后，列宽都会按记录恢复
- 没有记录的列按星号均分宽度

### 导入 / 导出
- 导入 CSV：**新建表，表名取 CSV 的文件名**（不含扩展名；文件名为空时回退到 `未命名01` 递增格式）
- 导入时按位置对应列、视作无任何配置的列，**第一行也当数据**，且**所有字段写入前 trim**
- 导出：**全部表**，每张表一个 CSV（表名做文件名清洗，重名自动加序号）
- 编码：读入自动识别（BOM → UTF-8 → 系统 ANSI/GBK 回退）；写出 UTF-8 with BOM + CRLF

### 备份 / 恢复
- **本地备份**：手动触发，用 SQLite 在线备份 API 生成一致的快照，带时间戳放 `Backup\`
- **WebDAV 备份**：手动触发，**只上传正式的 sqlite**（先做一致快照再传）
- **WebDAV 恢复**：在**远端备份列表**里选一个文件，**先自动本地备份当前库**，再下载覆盖；恢复前校验文件确实是有效 SQLite
- 下载先写临时文件、成功后才覆盖，**失败的下载不会破坏现有文件**
- 覆盖主库同样先写同目录临时文件再替换；失败时重新打开原来的库，不把连接留在关闭状态
- 上传/下载有进度提示，可取消
- 恢复后**自动重启软件**

### 远端备份文件名：前缀 + 时间戳

上传**不指定固定文件名**，而是自动生成：

```
<前缀>_yyyyMMdd_HHmmss.sqlite      例如 DataManager_20261009_233045.sqlite
```

这样做的好处：

- **不依赖服务器的 PUT 覆盖语义**。有些 WebDAV 服务对已存在的文件不会真正覆盖，
  固定文件名会导致“上传成功但内容一直是旧的”；每次换新名字就完全绕开了这个问题。
- **历史备份自动保留**，等于免费的版本管理，可以回滚到任意一次上传。

界面上的 **文件名前缀** 决定这个名字（默认 `DataManager`），只需填前缀，不要填完整文件名。

### 从 WebDAV 恢复

因为远端文件名带时间戳，恢复不再是“下载固定的那一个文件”，而是：

1. 点 **刷新远端备份列表** → 程序用 `PROPFIND` 列出【远端目录】下的所有 `.sqlite`；
2. 列表按时间倒序，**选中要恢复的那一份**；
3. 点 **从选中的远端备份恢复** → 先自动把当前库备份到本地 `Backup\`，再下载覆盖。

恢复列表同时显示大小与时间（优先用服务器返回的 `getlastmodified`，
拿不到时从文件名的 `yyyyMMdd_HHmmss` 解析）。

### 远端目录（为什么需要填）

WebDAV 的 **PUT 不会自动创建中间目录**。往一个不存在的目录里 PUT，服务器只回 **404**，
看起来就像“地址填错了”——这也是其它 WebDAV 客户端都要求先选一个已存在目录的原因。

| 配置项 | 说明 |
|---|---|
| 地址 | WebDAV 基地址，例如 `https://dav.jianguoyun.com/dav/` |
| **远端目录** | 相对基地址的目录，例如 `DataManager`。**留空 = 直接存在基地址目录下** |
| 文件名前缀 | 例如 `DataManager`；实际文件名 = `前缀_日期_时间.sqlite` |

- 点击上传时，程序会先对该目录发 **MKCOL 逐级创建**（已存在则跳过），再 PUT 文件，
  所以**目录不存在也能直接上传**，不必事先去网盘手动建。
- 「测试连接」除了验证账号，还会顺带告诉你配置的目录**当前是否存在**。
- 若服务器不支持 MKCOL，会明确提示让你先手动建目录，而不是等到 PUT 才报一个含糊的 404。
- 目录名支持中文与多级（`a/b/c`），会自动做 URL 转义。
- 上传失败时的报错会附上**实际请求的完整地址**，方便核对路径。

### 备份为什么不会“被自己锁死”（重要）

设置窗口打开期间，连接上挂着一个未提交的 `BEGIN IMMEDIATE` 事务（建表/加列/删列都在这个事务里，点保存才提交）。
早期版本直接用这条连接做备份，会被**自己的写锁**挡住：`sqlite3_backup_step` 与 `sqlite3_backup_finish`
双双返回 `SQLITE_BUSY`，于是出现「WebDAV 测试连通成功，但一上传就失败」——因为上传的第一步就是做快照，
服务器根本没收到 PUT。

现在 `SqliteConnection.BackupTo` 的处理：

1. 若本连接有未提交事务，**另开一条只读连接**读取已提交状态再备份（语义上也正好是“只备份已保存的数据”）。
2. 写入目标前先落到 `<目标>.partial`，全部成功后替换目标文件；**任何失败都会清掉 .partial**，
   不再留下 0 字节残留文件。
3. 备份失败时读 `sqlite3_errstr` 与本/源连接的 errmsg，给出可读中文，
   不再出现 `备份数据库失败：not an error` 这种误导信息。

启动时还会清理历史遗留的 `*.sqlite.partial`。
